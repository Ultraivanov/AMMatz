### Current Visual System

- Palette: deep navy background (`#06284f` family), white text, translucent white grid/borders, orange accent (`#ff6b35`).
- Typography: Inter for prose/interface, IBM Plex Mono for technical labels.
- Layout: max-width 1440px, 12-column grid, 120px desktop side padding, 24px gutters, 72px section gaps.
- Motifs: blueprint/spec box, target mark, technical borders, microscopy imagery, inline schematic logo.
- Responsive behavior: collapses to single-column layouts under 900px, tighter typography under 580px.

### Technical Risks

- HTML is a single static document with inline CSS and embedded base64 images, currently about 3.8 MB.
- Assets need extraction, naming, compression, explicit dimensions, and lazy loading below the fold.
- Some semantic content is rendered as long paragraphs; production page should improve scanning without rewriting scientific claims casually.
- `♻` icon should be replaced for brand consistency and accessibility.
- `mailto:` is acceptable for MVP but weak for conversion tracking and form validation.
- Need final decision on framework, deployment target, and analytics/contact requirements before implementation.

## Refined Design System Notes

### Direction

The generated baseline was replaced with a custom AMMatz design-system master. The site direction is industrial B2B, blueprint precision, laboratory evidence, and controlled technical energy.

### Key Decisions

- Preserve the current AMMatz navy/white/orange identity.
- Use Inter for primary typography and IBM Plex Mono for specs/labels.
- Map future shadcn/Tailwind variables to AMMatz semantic tokens instead of ad hoc raw utility colors.
- Keep a one-page MVP structure: Header, Hero, Why, Powders, Technology, Recycling, Contact.
- Treat microscopy, equipment, blueprint, and plasma imagery as evidence assets.
- Replace emoji-style marks with consistent SVG/icon language.
- Defer contact form implementation decision to MVP requirements; keep `mailto:office@ammatz.com` as the current baseline.

## MVP Frontend Requirements

### Recommended Approach

Build a static-first Next.js App Router site with TypeScript, Tailwind, and shadcn/ui-compatible semantic tokens. This is the recommended approach because AMMatz currently needs a high-quality production landing page, SEO, asset optimization, deployment readiness, and room for a future form without prematurely adding backend complexity.

### Alternatives Considered

| Approach | Pros | Cons | Decision |
|---|---|---|---|
| Static HTML/CSS cleanup | Fastest path from current file | Harder to scale, weaker component structure, less production tooling | Reject |
| Vite React SPA | Simple and lightweight | SEO/metadata/deployment conventions require more manual work | Reject |
| Next.js static-first | Strong SEO, image/font optimization, straightforward Vercel path, good shadcn compatibility | Slightly more framework overhead | Choose |

### Stack

- Next.js App Router with TypeScript.
- Tailwind CSS for tokenized styling.
- shadcn/ui components only where they improve structure: Button, Card/panel primitives, Separator, possibly Sheet for mobile nav and form components if a form is added.
- Icon library: lucide-react unless the scaffold selects a different shadcn icon library.
- Static content in typed data files for the MVP landing page.

### MVP Page Scope

One production landing page:

1. Header
2. Hero
3. Why AMMatz
4. Our Powders
5. Our Technology
6. Metal Recycling
7. Contact

No multi-page routing in MVP unless required by deployment/SEO metadata files.

### Asset Strategy

- Extract all base64 images from the current HTML into `public/assets`.
- Use descriptive kebab-case filenames.
- Preserve original source images before optimization if practical.
- Convert production display assets to WebP/AVIF where supported by tooling.
- Use explicit image dimensions or stable aspect-ratio containers.
- Lazy-load below-fold imagery.

### Content Strategy

- Start from current HTML copy.
- Improve scannability by splitting long paragraphs and using structured bullet groups.
- Do not invent certifications, clients, capacity numbers, test results, or regulatory claims.
- Keep `office@ammatz.com` as the baseline contact path.

### Verification Requirements

- Local dev server runs.
- Production build succeeds.
- Responsive checks at 375, 768, 1024, and 1440px.
- No horizontal scroll on mobile.
- Images render and do not cause layout shift.
- Keyboard focus is visible for nav and CTA links.
- No emoji icons remain in UI.
- Basic metadata and Open Graph image strategy are present.
